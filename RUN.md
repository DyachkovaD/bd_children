# Запуск проекта (бэкенд + фронтенд)

Фронтенд раздаётся тем же Django-сервером, поэтому достаточно запустить бэкенд — в браузере будут и интерфейс, и API.

## 1. Окружение и зависимости

Виртуальное окружение создаётся в **корне проекта** `bd_children`. Все команды ниже — из корня:

```bash
# Создать виртуальное окружение (один раз)
python -m venv venv

# Активировать (Windows PowerShell)
.\venv\Scripts\Activate.ps1

# Или cmd
.\venv\Scripts\activate.bat

# Установить зависимости
pip install -r requirements.txt
```

## 2. База данных PostgreSQL

- Убедитесь, что PostgreSQL запущен и создана база для проекта.
- В папке **backend\src** создайте файл **.env** (если его ещё нет):

```
DB_NAME=имя_базы
DB_USER=пользователь
DB_PASSWORD=пароль
DB_HOST=localhost
DB_PORT=5432
```

## 3. Миграции и статика

Из папки **backend\src**:

```bash
cd backend\src

# Применить миграции
python manage.py migrate

# (Опционально) Собрать статику для деплоя через Waitress
python manage.py collectstatic --noinput
```

При необходимости создайте суперпользователя и тестовые данные:

```bash
python manage.py createsuperuser
python manage.py create_children
```

## 4. Запуск сервера

Все команды выполняются из папки **backend\src**.

### Вариант A: режим разработки (Django runserver)

```bash
cd backend\src
python manage.py runserver
```

- Сайт: **http://127.0.0.1:8000/**
- Админка: **http://127.0.0.1:8000/admin/**
- API: **http://127.0.0.1:8000/api/**

### Вариант B: через Waitress (как при деплое)

```bash
cd backend\src
python run_waitress.py
```

Тот же адрес: **http://127.0.0.1:8000/** (или **http://localhost:8000/**).

Порт можно задать переменной окружения:

```bash
set PORT=8080
python run_waitress.py
```

## 5. Проверка

1. Откройте в браузере: **http://127.0.0.1:8000/**
2. Должна открыться страница входа «Учёт учащихся».
3. Зарегистрируйте пользователя или войдите (если уже создан).
4. После входа доступны разделы: **Школы**, **Учащиеся**, **Статистика**.

Если при первом запуске нет школ и учеников — создайте их через интерфейс или выполните `python manage.py create_children` (из `backend\src`).

## 6. Диагностика прав пользователя

Если пользователь с ролью не может получить доступ к `GET /api/schools/` (ошибка «Недостаточно прав»):

```bash
cd backend\src
python manage.py check_user_permissions <имя_пользователя> --fix
```

Команда покажет роли, разрешения и рекомендации по исправлению.

**Частые причины:**
1. **Пользователь не привязан к роли** — Разрешения → выберите роль → кнопка «Пользователи роли» → отметьте пользователя.
2. **В роли нет view_school** — редактируйте роль и отметьте разрешение «Просмотр Школа» (view_school).
3. **Разрешения не инициализированы** — на странице Разрешений нажмите «Инициализировать».
4. **Смешение с Django Admin** — проект использует свою систему разрешений (приложение permissions), а не стандартные Django Groups/Permissions из `/admin/`.
